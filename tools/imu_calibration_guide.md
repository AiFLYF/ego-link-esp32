# IMU 交互标定动作表（feature/imu-validation 配套）

坐标约定（屏幕系）：**+x 向右，+y 向下，+z 垂直屏面朝外**。
（屏幕系的 z 与传感器原始 z 相同——轴向映射只在 xy 平面内旋转。）

固件每秒打印一行（**注意 2026-09-23 起 `scr` 是三个值**，因为 z 也要映射了）：

```
imu: src=<芯片> o=<方向档位> raw[x y z] scr[x y z] |a|=幅值
```

> ✅ **档位 `oN` 会显示在板端屏幕上**（倾角小字里，形如 `倾角 2° o0`），
> 而且**方向词是板端自己算的**（服务器文案优先、离线时用本地算的兜底）。
> 所以标定**完全不需要电脑**，连 WiFi 都不用。芯片名仍然只在串口日志里。

## 判读：每个数字从哪来

| 日志里的字段 | 含义 | 用在哪 |
|---|---|---|
| `src=` | 实际探测到的芯片（SC7A20 / LIS3DH / QMA7981 / MPU6050 / Buttons） | 确认板子焊的是哪颗 |
| `o=` | 当前方向档位 0..7 | 方向不对时看这个数 |
| `raw[x y z]` | 传感器原始坐标系的值 | 确认「竖直分量落在哪个原始轴」—— 这颗 SC7A20 竖装，落在 `raw y` |
| `scr[x y z]` | 映射到屏幕系后的 x/y/z | **平放时 `scr z` 应 ≈ +1.02**；P3–P6 的 x/y 也看这里 |
| `\|a\|` | 合矢量幅值 | 静止时应 ≈1.00 |

## 第一部分：六姿态验证（**每个姿态停 20 秒以上**）

> ⚠️ 日志大约 **11 秒才出一行**，停 3 秒是采不到的（文档原来写 3 秒，实测不够，已订正）。

| # | 动作 | 期望值 | 验证点 |
|---|---|---|---|
| P1 | 屏幕朝上平放在桌面 | `scr` 的 **z≈+1.00**，x≈0, y≈0 | 基准姿态、量程（\|a\|≈1.00） |
| P2 | 屏幕朝下扣在桌面（翻转 180°） | `scr` 的 **z≈-1.00** | Z 轴满程反向 |
| P3 | 板子立起来，**顶边朝上**（正常阅读方向） | `scr` y≈-1.00 | Y 负向 |
| P4 | 板子倒置，**顶边朝下**（与 P3 上下颠倒） | `scr` y≈+1.00 | Y 正向 |
| P5 | 板子**右边朝地**立起（顶边指向右） | `scr` x≈+1.00 ⚠️ 见下 | X 正向 |
| P6 | 板子**左边朝地**立起（顶边指向左） | `scr` x≈-1.00 ⚠️ 见下 | X 负向 |

> ⚠️ **P4 的原文写的是"底边朝下"，那是错的**（"顶边朝上"和"底边朝下"是同一个姿势，
> 但期望值却相反，自相矛盾）。正确说法是"**顶边朝下**"，与 P3 上下颠倒。
> 2026-09-23 订正。
>
> ⚠️ **P5/P6 的期望值待实测确认**。按加速度计物理（静止时读到的是"向上"方向的 1g，
> P1 的 `raw z≈+1.00` 就是这个约定的体现）：右边朝地 → 板子的"上"指向左边 → `scr x≈-1.00`，
> 与表里写的 **正好相反**。也就是说 P5/P6 这两行的期望值很可能**互相写反了**。
> 在真机上摆一遍就能定论 —— 把实测值填进下面的记录表，然后订正本表。

## 实测记录（真机摆一遍填这里）

> 每摆一个姿势停 3 秒，抄一行 `imu:` 日志。同一姿势下**档位换一次就重抄一遍**，
> 直到六个姿势全部吻合 —— 那个档位就是这块板子的正确值。

| 档位 `o=` | P1 raw z | P2 raw z | P3 scr y | P4 scr y | P5 scr x | P6 scr x | 判定 |
|---|---|---|---|---|---|---|---|
| 0 | | | | | | | |
| 1 | | | | | | | |
| … | | | | | | | |

判读规则：
- 每个姿态 \|a\| 都应在 0.95–1.05 之间 → 灵敏度（LSB/g）正确
- 每轴都能到 ±1.0 附近 → 无死轴、量程正确
- 方向与表一致 → orientation 映射正确；不一致则记录实际值反推正确档位

## 第二部分：八方向倾斜（平放，向各方向倾约 45°）

依次：上、右上、右、右下、下、左下、左、左上。
期望：倾斜方向与 `scr(x,y)` 的符号组合一致（如"上倾"→ y 负、"右倾"→ x 正）。
服务端 tilt_direction() 用同样契约，验证通过后网页 8 方位显示必然正确。

## ⚠️ 标定期间别双击 BOOT

新固件的按键映射是：**单击 = 问 AI，长按 = 切换方向档位，双击 = 进入配网**。
翻转板子时很容易手抖触发双击，一进配网就掉 WiFi、屏幕上换成配网页面，标定被迫中断。

- 想确认长按是否生效：**LED 两下短闪** = 档位已切换（单击只有一下，能区分）
- 万一误进配网：等它超时退出，或按屏幕提示操作后重来

## 若方向不一致（**纯屏上做，不用电脑、不用网**）

> 2026-09-23 起：板端界面在倾角小字里显示**当前档位 `oN`**，方向词也由**板端自己算**
> （服务器文案优先，离线时用本地算的兜底）。所以标定是**纯屏上操作**：

1. 把板子**平放**在桌上（屏幕朝上），**向右侧倾约 30°**。
2. 看板子屏幕左下角的**方向文字**：
   - 应该写「**向右倾斜**」
   - 如果写的是「向左 / 向上 / 向下」→ 方向不对
3. **长按 BOOT** 换一档（LED 闪两下 = 切换成功）。屏幕上的 `oN` 会变。
4. 重复 1–3，直到「向右倾斜」正确。再顺手验「向上倾斜」（把顶边朝你怀里倒）。
5. 找到的档位**已自动存 NVS**，掉电永久生效，不用重编译。

**为什么"平放 + 右侧倾"是最省事的判据**：平放时重力在 z 轴上（先确认 z 对了），
再只把左右倾角映射到 x 正负，一个动作同时验出"平面内旋转对不对"和"x 要不要取反"。

**想彻底免校准**：把找到的值写回 `ACCEL_ORIENT_DEFAULT`（`device/main/accel_input.c`）
并重烧，之后新板子出厂就是对的。

### 档位 `o0`–`o15` 的含义（2026-09-23 起是**完整三轴置换**，不是"只换 x/y"）

16 档 = {法线 = ±传感器 y} × {平面内 4 种 90° 旋转} × {右手 / 镜像}。
`out` 是屏幕系（+x 右、+y 下、+z 出屏），`in` 是传感器原始轴。

| 档位 | 映射 | 族 |
|---|---|---|
| o0 | out = (−in_x, +in_z, −in_y) | 法线 = −传感器 y |
| o1 | out = (+in_x, +in_z, −in_y) | 同上 |
| o2 | out = (+in_z, −in_x, −in_y) | 同上 |
| o3 | out = (−in_x, −in_z, −in_y) | 同上 |
| **o4** | **out = (−in_z, +in_x, −in_y)** | 同上 —— **本机实测正确** |
| o5 | out = (+in_x, −in_z, −in_y) | 同上 |
| o6 | out = (+in_z, +in_x, −in_y) | 同上 |
| o7 | out = (−in_z, −in_x, −in_y) | 同上 |
| o8 | out = (+in_x, −in_z, +in_y) | 法线 = +传感器 y |
| o9 | out = (+in_z, +in_x, +in_y) | 同上 |
| o10 | out = (−in_x, +in_z, +in_y) | 同上 |
| o11 | out = (−in_z, −in_x, +in_y) | 同上 |
| o12 | out = (+in_x, +in_z, +in_y) | 同上 |
| o13 | out = (+in_z, −in_x, +in_y) | 同上 |
| o14 | out = (−in_x, −in_z, +in_y) | 同上 |
| o15 | out = (−in_z, +in_x, +in_y) | 同上 |

**实测正确的档位是 `o4`**（2026-09-23 用户长按 BOOT 逐个试出来后亲眼确认，原话
「我确定以及肯定」），已写进 `ACCEL_ORIENT_DEFAULT`，新板子出厂就对。
（NVS 键名是 `orient3`；档位语义变过两次所以换了两次键名，旧值自动失效。）

> ⚠️ **平放这一个姿势区分不出平面内的 4 种旋转**：平放时 `in_x ≈ in_z`，
> 不同档位算出来的 `scr` 可能完全一样（实测 o0 和 o4 都是 `(−0.016, +0.016, +1.016)`）。
> **要定平面内旋转必须倾斜着试** —— 只看平放读数会误判。

### 备用：看串口日志

`imu: src=<芯片> o=<档位> raw[x y z] scr[x y z] |a|=幅值` —— **注意 `scr` 是三个值**
（z 也要映射了）。判读见上面「判读」表。实测这行大约 **11 秒**才出一条（不是 1 秒），
每个姿势要停够 20 秒以上才保证采到。

最有用的一条判据：**平放时 `scr z` 应该 ≈ +1.02**（不是 `raw y` 扛着竖直分量）。

### 2026-09-23 真机标定记录（根因已定位并修复）

- 板子：ESP32-S3-EYE + **后加的 SC7A20**（`BSP_CAPS_IMU 0`，官方 BSP 里没有这颗，
  所以**任何文档都查不到它的朝向**，只能实测）。
- **根因**：这颗 SC7A20 在这块板子上是**竖着装**的 —— **它的 y 轴才是板子的法线**。
  证据：板子平放（用户确认）时 `raw y ≈ −1.016`、`raw z ≈ 0.03`；
  而加速度计平焊时 z 必然垂直于板面，所以"z 是横的"只能是**装配方向**造成的。
- 原来的 8 个档位只做 xy 平面内的互换/翻转，**动不了 z 轴**，所以用户把 8 档全试一遍都不对。
- **修法**：改成完整三轴置换（见上表），默认 `o0`。
- **已确证的读数**（板子平放、屏幕朝上、`o0`）：

  ```
  imu: src=SC7A20 o=0 raw[+0.016 -1.016 +0.016] scr[+0.016 +0.016 +1.016] |a|=1.016
  ```

  竖直分量正确落到 `scr z`（+1.016），`scr x/y ≈ 0`，方向词为「水平」。
  **z 轴映射已确认正确。**
- **最终结论（用户实测确认）**：正确档位是 **`o4` = out(−z, +x, −y)**。
  已设为默认值，新板子免校准。平放读数 `scr z = +1.016`、`x/y ≈ 0` ✓。
- **我推错了两次，教训留着**：
  ① 按「LGA 封装的 z 轴必然垂直于 PCB」推出「只能是纯平面旋转」—— 错在把
     **芯片的 z 轴**当成了**板子的法线**（这颗芯片竖装，两者本来就不同轴）。
  ② 按用户「上下对、左右反」的**口头描述**推成「把 x 取反」—— 实际是平面内差 90°。
     而且平放姿势下 `in_x ≈ in_z`，**o0 与 o4 的读数一模一样**，光看平放数据分不出来。
  ⇒ **装配方向这种事，实测 > 推算；判据要拿「倾斜后的方向」，不是平放读数。**
- 顺带修的**离线可用性**：原来 `transport` 任务是"等 WiFi 才开始采样"，所以没网时
  屏幕完全没数据、方向词也不更新 —— 标定根本做不了。现在改成"采样和界面照常，
  没网时只跳过上报"。
- 期间订正的文档缺陷：P4 原文"倒立，底边朝下"自相矛盾（应为"顶边朝下"）；
  P5/P6 的期望值按物理推算应互换。

## 若读数异常

- 所有轴为 0：传感器没起来 → 看启动日志 `init done: source=...`，若为 `Buttons`
  说明芯片没探测到 → 贴出 I2C 扫描日志（探测失败时会全量打印）
- 启动日志里**没有** `init done:` 那行：说明初始化提前失败了，往上翻找 `ESP_LOGW`
  里的 `data read failed after init` / `data all zero after init`（这两个是新加的校验，
  命中就说明芯片探测到了但不出数）
- 单轴为 0 或数值乱跳：硬件问题（虚焊/断线），不是软件
- \|a\| 偏离 1.00（如 0.5 或 2.0）：自适应格式选错 → 贴日志里的 shift/scale，
  我按实测重设 candidates 权重或显式配量程
- 日志里偶发 `accel read failed (streak N, ~M ms) — samples dropped`：
  这是 I2C 瞬时读错，样本被丢弃（**不会**用假数据顶替）。偶发正常，
  持续刷屏才是总线问题
