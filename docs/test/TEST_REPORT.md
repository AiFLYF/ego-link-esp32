## 三、缺陷详情

### BUG-001 · P2 · 单板场景方向档位永远显示「还没收到板端上报的档位」

- **元素**：`D06-T01` `#orientnow`（指令记录卡片里的档位提示）
- **复现**：
  1. 只连**一块**板（`o=7`）；
  2. 打开仪表盘 → 看「远程操作 · 指令记录」里的档位提示。
- **预期**：`当前 第三组-07 = o7`
- **实际**：`（还没收到板端上报的档位）` —— 永远如此。再加一块板，两台的档位立刻都显示出来。
- **证据**：
  - `/api/devices` 明确返回 `"orient":7`（说明数据到了服务端）；
  - 单板时页面文案错误、双板时正确（见下方实测记录）；
  - 截图：`_qa_shots/run/live-1440.png`。
- **根因**：`server/web/index.html:2462`
  ```js
  if (list.length <= 1){
    card.hidden = true;
    devRows = {}; devSig = ""; devOrder = ""; devAges = {};
    var host0 = $("devs"); if (host0) host0.textContent = "";
    return;                    // ← 在这里就返回了
  }
  ...
  list.forEach(function(d){    // ← devOrient 只在这里被填
    if (d.orient !== null && d.orient !== undefined){ devOrient[d.id] = d.orient; ... }
  ```
  单板时提前 `return`，`devOrient` 永远是空对象 → `syncOrient()` 认为没数据。
- **为什么现有测试没抓到**：`tools/e2e_dashboard.js` 永远起**两块**假板子（一块带 oN、一块不带），
  正好绕开了 `length <= 1` 这条分支。这是"测试覆盖的是双板，产品默认是单板"的典型错位。
- **修复**（`5c93a82`）：把 `devOrient` 的更新提到早退之前 —— 档位显示与"画不画设备列表"无关；
  末尾那次 `syncOrient()` 删掉避免重复刷。`G09` 转绿。

### BUG-002 · P2 · 删除 SD 卡文件要确认两次，第二次写着「格式化 SD 卡」

- **元素**：`D11-B02` 文件列表里的「删除」
- **复现**：
  1. 板子在线 → 点「读取存储信息」，出现文件列表；
  2. 点某个文件的「删除」→ 弹「删除板子上的文件 / 将永久删除 CAM0001.JPG」；
  3. 点「确定」。
- **预期**：弹窗关闭，下发 `sd_rm`。
- **实际**：**又弹出一个**「格式化 SD 卡 / 板子上的 SD 卡会被整张清空…」；再点一次「确定」才真的删。
- **证据**：`_qa_shots/bug002-dialog1.png`、`_qa_shots/bug002-dialog2.png`；
  两次弹窗文案实测记录（见附录 A）。
- **根因**：两处确认叠加
  - `server/web/index.html:2227-2228` —— `renderSd()` 自己弹了一次确认，然后调 `sendCmd("sd_rm", ...)`；
  - `server/web/index.html:1874-1883` —— `sendCmd()` 发现 `CMD_UI.sd_rm.danger === true`，**又弹一次**，
    且标题/正文是**写死的**「格式化 SD 卡 / 整张清空」（那段文案本来只适用于 `sd_format`）。
- **影响**：① 文案把"删一个文件"说成"清空整张卡"，用户会不敢点；② 点一次没反应，会被当成"按钮坏了"；
  ③ 真正的危险操作 `sd_format` 的文案因此也被稀释（每次都弹同样的字，用户会习惯性点确定）。
- **修复**（`267b3b2`）：`renderSd()` 改走 `doSendCmd()`，跳过 `sendCmd()` 里的通用确认
  （确认框已经按文件名弹过了，文案也是对的）。`L07` 转绿，`L08` 保持绿。

### BUG-003 · P3 · 「存储管理」空态没有引导文案

### BUG-006 · P2 · 项目主页在手机（375px）上横向溢出，代码块右侧被裁

- **元素**：`L04-B01/B02`（「闭环」一节的请求/响应代码块，含「复制」按钮）
- **复现**：手机宽度打开 <https://aiflyf.github.io/ego-link-esp32/>（或本地 `docs/index.html`），
  滚到「一条真实数据的闭环旅程」。
- **预期**：代码块与视口同宽，长行在块内横向滚动。
- **实际**：`document.documentElement.scrollWidth = 492 > 375`；`body{overflow-x:hidden}` 把右侧
  **裁掉**（不是滚动），`TELEMETRY.JSON` 那块的「复制」按钮完全点不到。
- **证据**：`_qa_shots/landing-loop-375.png`（代码块右边缘被切）、`_qa_shots/landing-375.png`。
- **根因**：`docs/index.html:226` `.payloads{display:grid;grid-template-columns:1fr 1fr}`。
  `1fr` 轨道的**自动最小尺寸**取的是 grid item 的 min-content —— `.code` 里的 `<pre>` 是
  `white-space:pre`，最长一行把轨道撑到 **465.5px**，比 375px 视口还宽。

- **改法**：`.payloads > *{min-width:0}`（或给 `.code` 加 `min-width:0`），
  让轨道能收缩，`pre{overflow-x:auto}` 才会真正生效。
- **修复**（`7a0c933`）：加 `.payloads>*{min-width:0}`。`Q08` 转绿（scrollWidth 回到 375）。
